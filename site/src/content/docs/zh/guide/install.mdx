`agent-presence` 运行于 **macOS 和 Linux**(不支持 Windows),需要 Node.js 22.13 或更高版本。凭据保存在 macOS 的 Keychain、Linux 的 libsecret 中。

已使用 0.9.0 或更早版本的用户，请先按[升级指引](#从-090-或更早版本升级)操作，再替换安装的包。

## 全局安装

<Tabs syncKey="pm">
<TabItem label="pnpm">

```bash
pnpm add -g @rivus/agent-presence
agent-presence setup
```

</TabItem>
<TabItem label="npm">

```bash
npm i -g @rivus/agent-presence
agent-presence setup
```

</TabItem>
<TabItem label="bun">

```bash
bun add -g @rivus/agent-presence
agent-presence setup
```

</TabItem>
</Tabs>

`setup` 先列出配置冲突和允许的处理方式，按你的选择重新规划，再展示完整变更、命令和预期信任提示。确认计划后才会写入智能体配置。取消、拒绝确认或遇到受保护目标时，setup 会退出。登录和本地目录迁移可能已经写入各自的数据。

非交互终端可用 `setup --yes` 应用无冲突的计划，但它不会自动处理冲突。交互终端始终会请求明确确认，包括传了 `--yes` 时。应用计划后，setup 会询问是否安装可选的 dsh 插件、安装 macOS 电源 watcher、配置 provider，最后验证安装的 bundle。Linux 跳过 watcher，依靠 TTL 清理。

</TabItem>
<TabItem label="npm">

</TabItem>
<TabItem label="bun">

</TabItem>

如果智能体环境启动 hook 时 `PATH` 很窄，让稳定的 hook shim 调用绝对路径下的 Node 和 CLI：

```bash
agent-presence setup --hook-command absolute
```

默认 provider 是 `magic-builder`,所以首次 `setup` 会先跑扫码登录(保存 slot 凭据),再提示粘贴一个 Magic-Builder token。无需 token 的备选见 [Provider](/zh/guide/providers)。

## 从 0.9.0 或更早版本升级

如果 setup 列出先前保留的文件，请先将它们移出旧安装位置，不再需要时也可删除。即使同时列出了需要替换的项目，也必须先处理保留文件，再运行任何旧卸载器。其余旧安装在升级前运行旧版本自己的卸载命令，不加 `--credentials` 或 `--all`，以保留凭据、配置和状态：

```bash
npx --yes @rivus/agent-presence@<previous-version> uninstall
```

使用旧 hook 命令固定的版本；有多个不同版本时分别运行。匹配到的 hook 命令没有固定版本时，使用迁移到 harness 前的最后一个版本 `0.9.0`。从 checkout 安装的用户可在更新 checkout 前运行 `node <checkout>/dist/src/cli.js uninstall`。然后安装本版本，再运行 `agent-presence setup`。不要使用未固定版本的卸载命令：本版本只移除 harness 安装记录中的智能体产物，不处理记录之外的旧版本项目。后续升级由 setup 原地更新安装记录，无需先卸载。

setup 检测到旧版本项目时，会列出智能体、路径和类型，hook 还会列出事件和命令，然后在队列恢复、登录和安装确认前以非零状态退出。智能体目标和队列文件保持不变；此前可能已经执行获准的旧目录迁移。`--no-hooks` 跳过此检查。

- 标为需要替换的项目使用上面的旧版本卸载命令。卸载后仍留下的改名插件副本或手改项目，按列出的路径手动移除。
- 标为先前保留的文件属于用户，请手动移动或删除；不要为这些文件运行旧卸载器，它会删除用户保留的文件。

本版本忽略以下旧安装目标覆盖变量。setup 会逐一列出已设置的变量，包括拒绝继续安装时。运行旧版本卸载时，须保持它们原来的值，否则这些目标中的旧产物会留下，也不在本版本的检查范围内：

```text
CLAUDE_SETTINGS_FILE
GEMINI_SETTINGS_FILE
CODEX_HOOKS_FILE
OPENCODE_CONFIG
OPENCODE_AGENT_PRESENCE_PLUGIN_FILE
OPENCODE_AGENT_SIGNATURE_PLUGIN_FILE
PI_SETTINGS_FILE
PI_AGENT_PRESENCE_EXTENSION_FILE
PI_AGENT_PRESENCE_EXTENSION_DIR
```

checkout 路径不含 presence 标记的旧绝对路径 hook 命令无法被检查识别。旧卸载器通常能移除不带引号的形式；带空格等需要引号的 checkout 路径也可能逃过旧卸载器。请检查智能体配置，手动移除残留的旧命令，否则它会与新 hook 一起执行；`doctor` 也无法识别这种重复。旧卸载器还会移除 Claude、Codex 或 Gemini 中所有包含 `dist/src/cli.js hook` 的 hook，包括其他工具的 hook；必要时先保存再恢复这些无关项目。

旧卸载器还会移除 dsh 插件和 macOS watcher；setup 会再次询问 dsh，并重新安装 watcher。Codex 切换到稳定 shim 的 `hook --agent` 命令预计需要重新信任一次 hook。后续仅替换 shim 的升级保持已安装 hook 的定义稳定。

## 安装位置

以下是默认的用户目录位置；覆盖智能体 home 时，计划会显示解析后的实际路径。

| 智能体      | 管理的产物                                                                                                                                                                                                                  |
| ----------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Claude Code | `~/.claude/skills/agent-presence/` 中的插件，含 `.claude-plugin/plugin.json` 和 `hooks/hooks.json`；setup 不向 `~/.claude/settings.json` 添加 hook。                                                                        |
| Codex       | `codex` CLI 可用时，在 `~/.codex/plugins/agent-presence/` 创建 marketplace/plugin，通过 `codex plugin` 在 `~/.codex/config.toml` 中注册；Codex 运行安装到缓存中的副本。CLI 不可用时，hook 分组写入 `~/.codex/config.toml`。 |
| Gemini CLI  | `~/.gemini/extensions/agent-presence/` 中的扩展，含 `gemini-extension.json` 和 `hooks/hooks.json`。                                                                                                                         |
| Grok        | 独立的 hook 文件 `~/.grok/hooks/agent-presence.json`。                                                                                                                                                                      |
| opencode    | 桥接文件 `~/.config/opencode/plugins/agent-presence.js`。                                                                                                                                                                   |
| Pi          | 桥接文件 `~/.pi/agent/extensions/agent-presence.ts`，由扩展目录自动发现。                                                                                                                                                   |

dsh 插件和 macOS 电源 watcher 仍由 presence 自行管理，不属于 harness bundle。交互式 setup 检测到 dsh 时，会询问是否安装 `~/.dsh/plugins/agent-presence.mjs` 并在 `~/.dsh/cordis.patch.yml` 中注册。

所有 harness hook 都调用 `~/.agent-presence/bin/agent-presence`。setup 以原子替换方式更新 shim，使其调用当前安装版本的包；`--hook-command absolute` 则保存解析后的 Node 和 CLI 路径。两种模式安装到智能体中的 hook 命令相同。默认模式仍依赖 `npx` 及其包缓存；绝对路径模式要求 checkout 持续可用。

命令式 hook 中，Claude Code、Codex 和 Grok 按秒写入 `timeout: 5`，Gemini 按毫秒写入 `timeout: 5000`。opencode/Pi 桥接仅对同步结束事件的交付设置 5000 毫秒子进程超时；其他事件异步发送，不设置子进程超时。Gemini 使用 `SessionStart`、`BeforeAgent`、`BeforeTool`、`AfterTool`、`AfterAgent` 和 `SessionEnd`。Claude 插件位置避免向 Cursor 也会读取的 settings 文件添加 presence hook；presence 不安装 Cursor 源。

现有 Codex 注册切换到 shim 的 `hook --agent` 命令后，预计需要重新信任一次 hook。请查看计划列出的提示，通过 Codex 批准；setup 不会修改信任状态。后续仅替换 shim 时，已安装 hook 的定义保持稳定。真实 Claude 插件加载、Cursor 行为、Codex 信任提示和 Gemini 扩展加载仍需单独验收，隔离环境中的产物检查不能证明这些行为。支持扩展的最低 Gemini 版本尚未确认。

## 检查与卸载

```bash
agent-presence doctor
agent-presence inventory
agent-presence uninstall
```

`doctor` 检查 hook 和 harness 安装记录的健康状态；警告或错误会导致非零退出码。重复检查同时使用 presence 专属的旧版本标记和已安装命令，覆盖命令式 hook 文件，不覆盖 opencode/Pi 桥接文件。它也会检查其他工具的 hook，因此其他工具的警告也可能导致退出码 1。`inventory` 展示共享的 kit 安装记录，包含其他应用的条目。两个命令都支持 `--json`，完整限制见[命令](/zh/reference/commands/)。

`uninstall` 报告移除的产物及每个保留位置和原因，再独立移除 shim、dsh 插件和 macOS watcher。默认保留凭据、配置和 session 状态。智能体产物只按 harness 记录移除；旧版本 hook 不会自动加入该记录，应按上面的升级步骤用对应版本移除。
