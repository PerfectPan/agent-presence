'@rivus/agent-presence': minor

Usage scanning for Claude Code, Codex, Gemini CLI, opencode, Pi, and Grok now runs through `@rivus/agent-kit`'s transcript decoders in one stateless scan per window, replacing the hand-rolled per-agent scanners. Token totals are unchanged; badges read the same on the same transcripts. The decoding corrections that come with it: Codex prices each record with its rollout's own service tier (priority processing ×2) instead of applying the current `~/.codex/config.toml` tier to every record, and counts `token_usage_record` entries it previously dropped; Gemini CLI counts a migrated chat once (from its `.jsonl` file) and now counts tool-use prompt tokens; Claude Code de-duplicates a request by its request id alone, so copies under a different message id no longer double-count; Pi skips the parent entries copied into a forked session. Grok's completed turns now contribute usage with the cost Grok logged. `CODEX_HOME`, `PI_CODING_AGENT_DIR`, and `GROK_HOME` now locate transcripts for the scan, and a set `GEMINI_CLI_HOME` points at `$GEMINI_CLI_HOME/.gemini/tmp` (matching Gemini CLI's own layout) instead of `$GEMINI_CLI_HOME/tmp`. Two accepted behavior changes: an active Claude Code session's newest requests appear once four newer requests have been written in their lane or the session has been quiet for 30 minutes, and an `opencode.db` that exists but cannot be read no longer falls back to the legacy JSON store — its contribution is empty. `agent-presence usage --json` reports `inputTokens` cache-inclusive (cache reads and writes are subsets of it) and `totalTokens` as `inputTokens + outputTokens`, matching what the agents themselves report.
